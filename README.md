# 冷链舱位温度台

冷柜舱位**先预约、点亮后才能写温度**。记录员在舱位预约落地页登记舱号与预约时段并点亮；提交温度时必须点选**仍亮着**的舱号，点到已熄舱或未选舱，整笔退回并写清原因。舱号随温度单落档后**冻住**，事后熄舱改不了旧单舱号。

## 业务规则

1. 预约落地页（顶栏「舱位预约」入口，独立整屏页面）登记舱号 + 预约时段，点亮该舱；舱号不可重复预约。
2. 亮灭判定前后端共用同一口径（`backend/rules.py::is_reservation_lit`）：状态为亮且当前时间在预约时段 `[开始, 结束)` 内。页面亮舱表、提交入库校验都走它。
3. 提交温度只接收「点选的亮舱 id」，后端在**单条事务**内行锁校验亮舱、冻结舱号并插入温度单，不存在“先入队再改舱号”的半截单。
4. 同一亮舱至多挂一单：两名记录员并发撞挂，至多一笔入队，另一笔当场 409 拒收（部分唯一索引 + 行锁兜底）。
5. 熄舱后该舱不能再写温度，旧温度单的舱号不变；预约表可翻「亮舱表」与「熄舱流水」。
6. 值班员只读：可看预约表、亮灭流水和温度单，不能登记/熄舱，也不能提交温度。
7. 后台工人用 `FOR UPDATE SKIP LOCKED` 认领候审单，按 **8℃** 上限判定 **合格** / **超温**。

## 技术栈

| 层 | 选型 |
|----|------|
| 接口 | Python aiohttp + asyncpg |
| 工人 | `worker.py`（psycopg，`FOR UPDATE SKIP LOCKED`） |
| 页面 | Preact + Vite，nginx 反代 `/api` |
| 数据库 | PostgreSQL 16 |

## 种子数据

预约表预置一条亮舱预约：**舱甲零一**（预约时段覆盖启动时刻）。温度单流水预置两条已办结样例：

| 探头 | 温度 | 结论 |
|------|------|------|
| 探头A01 | 4.2℃ | 合格 |
| 探头B02 | 12.5℃ | 超温 |

## 验收路径

1. logger 登录 → 顶栏「舱位预约」→ 舱甲零一已点亮（种子）→ 回总览点亮舱「舱甲零一」提交温度 → 进候审，办结后舱号仍显示「舱甲零一」。
2. 在预约页把「舱甲零一」熄舱 → 再提交同舱 → 整笔退回，提示「已熄舱，不能写温度」。
3. logger 与 logger2 同时对同一亮舱提交 → 只成一笔，另一笔当场拒收。
4. watcher 登录：预约页无登记/熄舱按钮，总览无提交表单。

## 本地开发（可选）

```bash
# 需本机 PostgreSQL 或仅起 db 容器
cd backend && pip install -r requirements.txt && python api.py
cd backend && python worker.py
cd frontend && npm install && npm run dev
```

接口进程默认监听容器内 **8000**，对外映射 **8197**。
