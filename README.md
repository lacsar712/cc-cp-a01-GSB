# 冷链探头超温台

冷柜舱位**先预约点亮**才能写温度：记录员在「舱位预约」落地页登记舱号与预约时段并点亮；提交温度时必须点选一个**仍亮着的空舱**，点到已熄舱、非时段或已挂单舱，温度整笔退回并写清原因。后台工人用数据库行锁认领待处理队列，按 **8℃** 上限判定 **合格** 或 **超温**。

## 舱位规则

1. **先约后写**：未登记预约或灯已熄灭的舱不能提交温度。
2. **亮灭判定前后端同口径**：`backend/rules.py` 的 `slot_writable` 与 `frontend/src/slotRule.js` 逐条对应——灯亮且当前时刻落在预约时段内才可写。
3. **入队与舱号冻结原子落库**：提交在单事务内「锁预约行 → 判定亮灭/时段/空选 → 舱号随单 INSERT」，不存在可改舱号的半截单。
4. **一舱一单**：同一预约至多挂一笔单据；两名记录员并发撞挂同一亮舱，由行锁 + 唯一索引兜底，至多一笔入队，另一笔当场 409 拒绝。
5. **舱号随单冻结**：舱号冗余在单据上，熄舱只改预约表，旧单舱号永不被改写。
6. **值班员只读**：可翻预约表（亮舱表 + 熄舱流水）与冻住的舱号，不能改亮灭，不能提交温度。

## 技术栈

| 层 | 选型 |
|----|------|
| 接口 | Python aiohttp + asyncpg |
| 工人 | `worker.py`（psycopg，`FOR UPDATE SKIP LOCKED`） |
| 页面 | Preact + Vite，nginx 反代 `/api` |
| 数据库 | PostgreSQL 16 |

## 使用流程

1. 顶栏点「舱位预约」进入落地页，填舱号（如 `舱甲零一`）与预约时段，登记并点亮。
2. 回「温度总览」，在提交区点一个仍亮着的空舱（只列出可写空舱），填探头与温度提交，进入候审。
3. 后台工人认领并判定；办结后单据舱号永久冻为提交时的舱号。
4. 在预约页熄灭舱位后，再往该舱提交会被整笔退回（422，原因注明已熄灭/时段结束）。

## 接口

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| POST | `/api/auth/login` | - | 登录取 token |
| GET | `/api/slots` | 登录 | 预约表（亮舱表 + 熄舱流水，含挂单号） |
| POST | `/api/slots` | 记录员 | 登记舱号+时段并点亮（同舱亮灯中 409） |
| POST | `/api/slots/{id}/extinguish` | 记录员 | 熄舱（不影响旧单舱号） |
| GET | `/api/readings` | 登录 | 读数列表（含冻结舱号） |
| POST | `/api/readings` | 记录员 | 点选亮空舱原子挂舱入队；未选舱 400、已熄/非时段 422、撞车/非空 409 |
